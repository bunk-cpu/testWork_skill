# 文件生成与归档规则

适用范围：`D:\资源中心测试` 的所有测试、回归、复测、缺陷审核与交付。

## 先按业务端分类

- `资源中心前台`：资源中心首页、资源浏览列表、资源详情页、课程平台授权题库。
- `资源中心后台`：产品管理、资源管理、产品授权、上传资源及配置页面。
- 前台/后台指业务系统；缺陷由前端或后端开发修复不影响所属目录。已知页面分类记录在 [page-areas.json](page-areas.json)，新页面按用途确定所属端后补充。
- 共用工具、整理记录放在根目录 `通用测试资料`；TAPD 自动化自身验证放在其 `TAPD自动化` 子目录。skill 保持在根目录 `.agents/skills`。

```text
D:\资源中心测试\
├─ 资源中心前台\
│  ├─ <页面名称>\
│  │  ├─ 测试报告.html
│  │  ├─ 需求与设计\设计稿\
│  │  └─ <缺陷ID>\                 本条缺陷的全部独立材料
│  ├─ 测试汇总\                    同端跨页面首轮汇总与交付
│  └─ 回测结果\YYYY-MM-DD\HHmmss_批次名称\
│     ├─ 回测批次.json
│     ├─ 回测汇总.html
│     ├─ 需求与范围\
│     └─ <页面名称>\<缺陷ID>\       本轮独立证据与结论
├─ 资源中心后台\                   内部结构同前台
└─ 通用测试资料\TAPD自动化\         工具自身测试与回测
```

新批次取实际执行开始时间，时区 Asia/Shanghai。历史批次只能确认日期时保留原批次名，不用复制或整理时间补造时分秒。同一轮继续执行复用原批次，新一轮另建批次；禁止覆盖首轮或上一轮同 ID 缺陷的报告和证据。

## 生成顺序

1. 确认所属端及首轮/回测类型，使用目录工具分配输出目录，并显式传给测试、截图、日志和报告生成代码。旧脚本执行前检查输出配置，不能继续写入旧的根目录路径。
2. 单条缺陷的 TAPD 文本、HTML、截图、录屏、JSON、日志和测试文件放在本轮 `<页面>/<缺陷ID>` 内，禁止跨缺陷混放。同一证据分别保留；较大共用文件可保留一份，每条相关缺陷提供明确索引。
3. 页面级报告、执行记录和需求放在对应页面；回测汇总、审核清单、需求范围、交付 ZIP 放在本轮批次。同端首轮跨页面汇总放在该端 `测试汇总`。跨前后台的测试在两端分别归档，并在汇总中互相链接。
4. 更新根目录和所属端导航、页面归档索引、回测目录、报告附件链接、JSON 文件索引与交付 ZIP；大小与 SHA-256 对应实际文件。历史原始包和 TAPD 提交内容快照保留为可核对的原始记录。

## 输出目录工具

以下命令由代理在 skill 目录执行，使用返回 JSON 的 `area`、`resultBase` 和 `outputDirectory`：

```powershell
# 已知页面自动识别所属端；新页面必须指定 --area frontend 或 backend
python -X utf8 scripts/result_paths.py --mode page --page '新建授权' --defect AUTH-001

# 新建后台回测，自动采用实际开始时间
python -X utf8 scripts/result_paths.py --mode retest --area backend --batch '已解决缺陷复测'

# 同一轮复用返回的 resultBase；以下日期和时间仅为格式示例
python -X utf8 scripts/result_paths.py --mode retest --base '资源中心后台/回测结果/2026-10-16/164500_已解决缺陷复测' --page '新建授权' --defect AUTH-001

# TAPD 工具验证：common 分类，不归入业务页面
python -X utf8 scripts/result_paths.py --mode retest --area common --batch 'TAPD脚本验证' --page 'TAPD自动化'
```

已有页面可省略 `--area`；不含页面的新批次必须显式指定。指定端与已知页面归属或复用批次不一致时拒绝写入。同秒同名批次自动追加序号。只有执行开始时间确有记录时才使用 `--started-at`，不能沿用示例时间。

## TAPD 清单目录

审核与提交授权遵循 SKILL.md。`resultBase` 始终相对于工作根目录：

- 首轮：`资源中心前台` 或 `资源中心后台`。
- 回测：`<所属端>/回测结果/YYYY-MM-DD/实际批次`。
- 工具自身验证：`通用测试资料/TAPD自动化`，或其下的回测批次。

`descriptionFile`、`attachments` 也相对于 `D:\资源中心测试`，并且必须位于该 `resultBase` 下的 `<页面>/<缺陷ID>` 内。例如后台首轮清单：

```json
{
  "resultBase": "资源中心后台",
  "defects": [{
    "page": "新建授权",
    "id": "AUTH-001",
    "descriptionFile": "资源中心后台/新建授权/AUTH-001/TAPD.txt"
  }]
}
```

示例仅说明路径，完整清单仍需要项目、标题与实际用户审核记录。提交快照、状态、截图和页面执行记录随本轮保存。历史提交快照保留原始内容与指纹；目录迁移不表示重新审核或允许重复创建。
