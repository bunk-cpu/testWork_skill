# TAPD 浏览器自动化

通过 Playwright 操作 Chrome 页面。所有命令由代理执行，工作目录为 `D:\资源中心测试\.agents\skills\resource-test-tapd`；不要求用户运行终端命令。依赖 Node.js 20+、Python、本机 Chrome 与 npm，首次使用执行 `scripts\setup.ps1`。

## 在同一个带窗口浏览器内执行

登录入口固定为 [TAPD 登录页面](https://www.tapd.cn/cloud_logins/login)。不从项目页触发登录，不读取历史保存的账号密码或环境变量凭据。用户名、密码、协议、验证码和二次验证均由用户在浏览器中自行操作。

1. 执行 `node scripts/tapd.mjs login`，启动可见浏览器并先检查实际登录状态。若已进入具有可访问项目链接或账号控件的页面，且没有登录表单，则记录 `mode: existing-session`，跳过手动登录和“已登录”告知；不能只看 cookie、历史状态文件、页面字数或一次跳转。
2. 只有确认为未登录时才保持窗口运行，由用户自行操作并在当前会话告知“已登录”。让出当前回合等待真实回复；收到后在 `.local` 下保存该消息来源（不含密码），执行 `confirm-login` 通知仍在等待的进程。该命令不访问浏览器配置文件，不与登录进程抢占会话。
3. 已有会话通过检查，或人工分支收到告知并核对实际状态后，保持浏览器和 `login` 宿主运行。看到“浏览器会话已就绪”即可发送后续命令；此时不要结束宿主进程或关闭窗口。
4. 登录完成后，请用户提供本次所属项目的准确名称；只采用本次执行中提供的信息。用户要求作为新用户时，重新获取项目及缺陷信息，不沿用历史账号、项目名、项目 ID 或提交清单；当前浏览器会话仍按实际页面检查。执行 `project --project-name`，从当前账号可访问项目的真实页面核对名称、项目 ID 和缺陷入口。不默认“数字教材”，不让用户额外查找项目 ID 或 URL。重名时再询问区分信息，不可见时核对名称和权限。
5. 后续命令通过 `.local` 下的本机会话请求交给原宿主，项目核对、表单检查、附件上传、创建与详情核对均由同一带窗口 Chrome 自动完成。不会为每条命令重启 Chrome，不切换无界面模式，也不在步骤间重复进入登录入口。浏览器窗口可以保持在用户视野中，用户无需逐步点击。整轮结束后执行 `close`。
6. 登录过期时，在原窗口执行登录流程并重新核对项目；已关闭的宿主不能通过旧状态文件恢复为“仍在运行”。防护拦截时保留窗口和诊断并停止；不尝试伪装自动化特征或反复重发。带窗口操作不能保证每次请求都通过平台防护。

```powershell
node scripts/tapd.mjs login
# 仅未登录分支：收到用户真实的“已登录”消息后保存来源，再执行：
node scripts/tapd.mjs confirm-login --source-file '.local\用户已登录告知.txt'
# 看到“浏览器会话已就绪”后，保持 login 进程运行，在另一命令中执行：
node scripts/tapd.mjs project --project-name '用户提供的准确项目名称'
node scripts/tapd.mjs inspect
node scripts/tapd.mjs inspect --form
node scripts/tapd.mjs status
# 整轮完成后：
node scripts/tapd.mjs close
```

`.local\browser-profile` 保存登录资料；`browser-session.json` 标识运行中的带窗口宿主，`browser-jobs` 保存命令及结果；`login-session.json` 保存本次登录状态，`project-context.json` 绑定本次登录。所有命令串行执行，宿主繁忙或已结束时拒绝新操作；请求超时不自动重发。切换账号后在原窗口重新登录并按名称选项目，旧项目不能沿用。不要复制、打包或公开 `.local` 和 `node_modules`。历史凭据不参与当前流程。`--headed`、`--manual` 保留兼容，所有线上操作默认使用现有带窗口会话。

检测到有效登录、用户告知登录成功、提供项目名称均不代表批准提交缺陷。同一次执行已取得的明确提交授权持续有效，不重复索要；没有本次提交授权时先完成材料并等待用户审核。用户要求按新用户执行时，不从历史清单恢复授权。

## 正文、字段与附件

生成缺陷正文时写出标题对应的环境、前置条件、复现步骤、预期结果、实际结果，以及明确的分级：

```text
【优先级】中
【严重程度】一般
……缺陷事实与步骤……
【相关文件】
- [操作录屏](操作录屏.mp4)
- [接口日志](接口日志.json)
- [测试文件](测试文件.xlsx)
- [截图](截图.png)
```

优先级、严重程度由生成缺陷材料时评定并写入正文。创建脚本读取正文中的值并填写对应字段，不再要求用户另列这两个值；正文缺失、冲突或与项目选项不匹配时停止，先核对材料，不猜测映射。也可使用 `优先级：中`、`严重程度：一般` 的独立行格式。

发现版本、模块、处理人交由用户创建后手动补填。脚本不设置这三个字段，即使旧清单中有值也忽略；保留项目自身默认值。它们为可选时不阻塞创建，项目将其设为必填且为空时停止，保留材料与表单证据，说明需由用户处理，不能填占位值。

附件直接根据正文实际引用的本地文件自动选择，不要求用户另给附件清单。新生成正文使用上述 Markdown 文件链接或反引号包裹的文件名，优先用相对于本条缺陷目录的路径，便于检查缺失文件；缺陷目录内正文明确提及的实际文件名也可识别。正文有同名文件时应改为准确路径。远程网页链接不是本地附件。正文引用的非图片文件自动上传，例如录屏、日志、JSON、测试文件、PDF、HTML。

图片不作为附件上传，包括 PNG、JPEG、WebP、GIF、SVG、BMP 等；脚本按扩展名并检查常见图片文件头排除。图片保留在本条缺陷目录，正文和报告中的图片引用继续保留。不把图片改名、转 PDF 或打包绕过规则；其他文档内已有图片无需拆分。

只选择正文引用的文件，不上传目录内全部文件。旧清单的 `attachments` 仅作定位提示，不会强制上传未被正文引用的文件。缺失引用、越过本条缺陷目录或其他批次的文件先按归档规则整理；共用证据为各缺陷独立保留，大型通用文件可提供明确索引，需实际上传时再将要上传的文件整理到对应缺陷目录并引用。自动选择结果、实际上传文件路径和 SHA-256 纳入内容快照与指纹。

## 提交清单与授权

参考 [未批准的格式示例](reviewed-manifest.example.json)。示例项目名称和 ID 是占位符，不可作为实际目标。先用 [result_paths.py](../scripts/result_paths.py) 和 [归档规则](result-layout.md) 确定结果目录：首轮清单放页面目录，同端跨页面放 `<所属端>\测试汇总\TAPD提交清单\`，回测清单放本轮批次，缺陷材料仍按页面与 ID 独立保存。

- `projectName`、`workspaceId`：必须与本次登录后按用户名称核对的项目完全一致，ID 来自真实页面，不由用户手填或沿用其他账号。
- `review.approved`、`review.source`、`review.approvedIds`：记录真实用户审核或提交指令和完全匹配的 ID 范围。不得由脚本自行批准。清单不是用户审核的替代品。
- `purpose`：默认 `reviewed-defects`。仅用户明确要求验证创建链路时使用 `creation-smoke`，同时要求 `review.kind: explicit-test-creation`，只含一条标题带“自动化验证”的记录，不扩大为业务缺陷或多条提交。
- `resultBase`：首轮填写 `资源中心前台` 或 `资源中心后台`；回测填写本轮已存在的 `<所属端>/回测结果/日期/批次` 相对路径，禁止混用历史批次。
- `page`、`id`、`title`：实际页面目录、独立缺陷目录 ID 和已审核标题；脚本自动补 `[本地ID]` 标记以便核对。
- `descriptionFile`：相对于工作根目录的 UTF-8 非空纯文本文件，位于本条缺陷目录；正文中包含分级和文件引用。按纯文本写入编辑器，不执行 HTML。
- `fields`：其他确有依据的业务字段，可省略。优先级、严重程度自动读正文；发现版本、模块、处理人不自动填写。`attachments` 可省略。

```powershell
node scripts/tapd.mjs validate --manifest 'D:\资源中心测试\资源中心后台\新建授权\TAPD待提交清单.json'
node scripts/tapd.mjs submit --manifest 'D:\资源中心测试\资源中心后台\新建授权\TAPD待提交清单.json'
```

`validate` 只检查本地文件，可检查未审核草稿，并列出解析后的字段和附件供核对。`submit` 先校验授权、正文分级、本次会话与项目，再由现有窗口创建；宿主接到命令时重新核对材料指纹，检查后变化的文件不会继续提交。

## 页面适配

项目存在自定义表单时先执行 `inspect --form`，按真实 DOM 调整 `config.json` 的 `selectors`；只有明确提交时才上传并点击创建。诊断资料通过 `result_paths.py` 存入新的 `通用测试资料\TAPD自动化\回测结果\日期\批次\TAPD自动化\`，不覆盖旧材料。控件元数据不记录输入框值，截图遮蔽密码框。

当前预设选择器来自已实际操作的表单：列表“创建”按钮打开新标签页 `/<实际项目ID>/bugtrace/bugs/add`，跟随 popup 后在 `#bug_form` 内定位 `#BugTitle`、描述 iframe 与附件 `#file_input`。页面存在同 ID 附件控件，必须限定表单范围。描述配置 `descriptionEditorId: BugDescription`，通过已核对的 TinyMCE 公共 API 写入转义后的文本和显式换行，提交前逐字核对。使用 `#_view` 创建，不点击“创建并继续”。这些预设不能证明其他项目所有表单都相同；无法唯一识别时停止，依据检查结果调整并验证。

可配置 `projectSwitcher`、`projectSearch` 以定位真实项目切换器；不可见项目需先检查实际页面，不能猜造项目链接。业务字段使用 `selectors.fields`。描述支持 textarea、contenteditable、iframe；字段支持文本、原生 select 和可核对选项的下拉框。

## 状态与恢复

每条缺陷保存 `tapd-payload.json`（正文、字段、实际附件 SHA-256）、`tapd-submission.json`（状态与链接）、提交前后截图或错误截图。页面目录保存 `TAPD提交执行记录.json`。这些本地截图也不作为缺陷附件上传。

创建前检查本地状态并按完整标题查重；列表过滤和权限可能限制远端查找，本地回执必须保留。同标题记录也要核对正文和附件，避免把不同内容的记录当作成功。每条只点击一次提交，随后在同一浏览器重新打开详情，核对目标项目、有效 ID、完整标题、正文和实际附件文件名，通过后保存 `tapd-detail-verification.json` 并登记成功。正文按空白归一后核对，附件核对名称；本地快照保存上传字节的 SHA-256，不将名称核对夸大为已下载远端附件逐字节校验。

- `submitted` / `already-exists`：指纹一致则跳过，内容变更则停止，不能再创建第二条。
- `failed-before-submit`：未点击提交，修复原因后可重试。
- `submitting` / `uncertain`：已进入提交或结果中断，禁止自动重试，先核实真实记录。

找到远端记录后执行：

```powershell
node scripts/tapd.mjs reconcile --manifest 'D:\资源中心测试\资源中心后台\新建授权\TAPD待提交清单.json' --id AUTH-001 --url '<实际TAPD详情链接>'
```

若人工确认确实未创建，只有用户明确同意重试后，保留原回执与核实说明，再改为 `failed-before-submit`。不得删除状态绕过保护。`.local\run.lock` 阻止并发；仅确认原进程已结束后移除残留锁。历史清单若不符合新规则，不修改既有成功回执来重新提交；需要变更时处理原缺陷。

## 验证范围

通过 `npm test` 在本地模拟页面验证，结果按当轮回测批次归档。运行测试前使用 `result_paths.py` 分配目录，可用 `TAPD_TEST_OUTPUT_DIRECTORY` 复用当前批次；未设置时测试脚本自动分配新批次。本地模拟数据不是实际用户授权，不连接 TAPD，不代表新账号或项目已完成线上创建。

2026-10-16 的 27 项本地回归通过，包括登录自动识别、跨命令连续创建、正文分级、非图片附件选择、详情核对、并发保护及结果不确定时禁止重试。

同日按用户明确指令完成一次真实创建验证：复用同一个带窗口 Chrome，跳过已登录环节，按本次项目名称核对目标，创建单条自动化验证记录；详情中的优先级、严重程度、正文及 JSON 附件核对通过，图片未作为附件上传，再次执行同一清单返回跳过。真实项目、缺陷链接及执行截图随本地批次保存，不随 skill 发布。

历史无界面访问曾遇到站点防护，当前采用首次成功案例的连续带窗口会话；上述验证不构成每次创建成功或每个账号、项目均适配的保证。
